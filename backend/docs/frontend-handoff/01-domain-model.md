# Domain Model

## Counting And Schema Rules

The module model inventory contains 42 Eloquent model classes under `app/Modules/*/Models` (excluding `Models/Concerns`). It includes business entities and operational/support records; it is not asserted to be a formally approved conceptual entity count. The migrations contain 70 `Schema::create` declarations across 27 files. The 68/89/108 counts in repository documents differ; see [README](README.md#known-unknowns-and-conflicts).

Standard conventions where actually applied: numeric BIGINT `id` primary key; a `publicUlid()` column is CHAR(26), ASCII/binary, unique; tenant records carry `company_id`; `$table->datetimes()` creates UTC-intended `created_at`/`updated_at` date-time columns. These are not universal: pivot/history/reference tables may lack ULID or timestamps. Most tenant FKs use composite company-scoped references and restrictive deletion. Exact columns/defaults/indexes are in the linked migrations; this section records all model entities, API-relevant fields, and verified relationships without treating every database field as an API field.

## Identity And Tenancy

- **User** — global identity/authenticatable. Schema: ULID; required first/last name, unique normalized email, password; nullable email/phone verification, phone, password-changed time, 2FA secrets/confirmation, lock/login metadata, timezone, last company; locale defaults `fr`, failed login attempts `0`, status `active`. `GET /me` exposes ULID/name/email/locale, `two_factor_enabled`, and platform roles only. Relationships: many-to-many companies through `company_users`; platform role/permission relations via Spatie. Source: [user migration](../../database/migrations/2026_10_01_000300_create_users_table.php), [User](../../app/Modules/Identity/Models/User.php), [MeResource](../../app/Modules/Identity/Resources/MeResource.php).
- **Company** — tenant root. Fields include ULID, `company_type` (`industrial|provider|brand`), status (default `pending_verification`), legal/trade names, tax/VAT/register IDs, country/currency, locale (default `fr`), timezone, address/contact/site metadata, nullable settings/onboarding JSON, approval/rejection/suspension/closure timestamps and actors. Unique country+tax ID; one company has many memberships and many tenant records. `GET /company` returns only ULID, type/status, legal/trade name, tax ID, currency, timezone. Source: [company migration](../../database/migrations/2026_10_01_000330_create_companies_table.php), [Company](../../app/Modules/Tenancy/Models/Company.php), [CompanyResource](../../app/Modules/Tenancy/Resources/CompanyResource.php).
- **CompanyUser (membership)** — belongs to one company and user; unique `(company_id,user_id)`, status defaults active, optional job title/inviter, joined/suspended/removed times. Source: [identity/tenant migration](../../database/migrations/2026_10_01_000340_create_identity_tenant_tables.php).
- **UserRoleAssignment** — company+user+role, optional site (`NULL` means all current/future company sites), generated site-scope key, optional grantor; unique per company/user/role/scope. Site assignment relates to one site; company membership FK guarantees membership. **UserInvitation** — company, email/name, role, nullable JSON site ULIDs (empty means all sites), unique token hash, `pending|accepted|revoked|expired`, pending uniqueness by company/email, inviter, expiry/resend/accept/revoke metadata. No invitation API route is present. Source: [assignment/invitation migration](../../database/migrations/2026_10_01_000520_create_user_role_assignments_and_invitations_tables.php), [UserRoleAssignment](../../app/Modules/Identity/Models/UserRoleAssignment.php), [UserInvitation](../../app/Modules/Identity/Models/UserInvitation.php).
- **Role / Permission** — Spatie-backed role and permission records. Role may be global (system) or company-specific and has name/guard/label/audience/system flag; permission has name/guard plus catalog module/scope/audience/label/order metadata. Roles have many permissions; role assignments connect user/company/site to role. Exact role/permission schema and pivot keys: [permission migration](../../database/migrations/2026_10_01_000320_create_permission_tables.php), [PermissionCatalog](../../app/Modules/Identity/Authorization/PermissionCatalog.php). No role-management endpoints are registered.

## Sites, Catalog, And Waste

- **Site** — tenant site with ULID, unique company+code, required name/code/country, kind default `production`, nullable address/city/postal/region/coordinates/regulatory identifier/timezone/capacity, `is_active` default true, activation/deactivation metadata. Belongs to company and country; has many zones, lots, thresholds, pickups, volumes, declarations. API fields: ULID, code/name/kind/city/region/timezone/capacity/is_active. Source: [sites/zones migration](../../database/migrations/2026_10_01_000500_create_sites_and_zones_tables.php), [Site](../../app/Modules/Sites/Models/Site.php), [SiteResource](../../app/Modules/Sites/Resources/SiteResource.php).
- **Zone** — site child; required code/name/type, optional kg/m³ capacity, alert percent default 90, waste-storage/active booleans default false/true; unique site+code. Has many lots/thresholds. Zone must belong to the lot/threshold site where checked.
- **WasteType** — tenant catalog variant: code/name required, optional linked global catalog item, description, regulatory code, optional packaging/color/treatment defaults, composition JSON, density/unit weight, extras; family and unit required; hazardous false and active true by default. Unique company+code. API excludes internal numeric IDs and includes ULID, code/name/description, hazardous, default grammage/composition, density/unit weight, extras, active flag. Source: [waste type migration](../../database/migrations/2026_10_01_000700_create_waste_types_and_stock_thresholds_tables.php), [WasteType](../../app/Modules/Catalog/Models/WasteType.php), [WasteTypeResource](../../app/Modules/Catalog/Resources/WasteTypeResource.php).
- **StockThreshold** — company/site plus optional zone and waste type, max kg, warning percentage default 90, nullable alert (`warning|exceeded`), alert/evaluation timestamps, active flag. Generated null-scope keys enforce uniqueness for site/zone/type target. Belongs to site, optional zone, optional waste type. API exposes ULID and related ULIDs, max kg/warning/alert/time/active. Source: same [catalog/threshold migration](../../database/migrations/2026_10_01_000700_create_waste_types_and_stock_thresholds_tables.php), [StockThresholdResource](../../app/Modules/Sites/Resources/StockThresholdResource.php).
- **WasteLot** — tenant/site/zone/type-bound material lot. ULID and company lot number; origin (`created|split|grouping`), status, nullable close reason, hazard flag, optional regulatory/packaging/unit/color, gross/tare/net kg, optional quantity, color/grammage/composition label/extras/notes, generated/status timestamps, actor/device IDs, version default 1, soft-delete metadata. Company+lot number unique; check net weight nonnegative and closed iff close reason is nonnull. Relationships: belongs to site/zone/type; has composition, tags, events; connects to operations through lineage and to pickups/documents through association records. API fields are in [WasteLotResource](../../app/Modules/Waste/Resources/WasteLotResource.php). Source: [lot migration](../../database/migrations/2026_10_01_000900_create_waste_lot_tables.php), [WasteLot](../../app/Modules/Waste/Models/WasteLot.php).
- **WasteLotComposition** — lot has many composition rows; material + percentage, unique lot/material, percentage >0 and <=100. **LotTag** — lot has many QR/RFID tags; global unique `(tag_type,tag_value)`, status active/unassigned/revoked, active flag, assignment/revocation/print metadata; at most one active tag per lot/type. **WasteLotEvent** — append-only event history; status/site/zone/weight/payload/source/actor/device/occurred/recorded fields; belongs to lot. **WasteLotOperation** — split/grouping operation with site, input/output kg, note, actor/times; has many lineage edges. **WasteLotLineage** — operation edges from parent to child lot, relation split/grouping and quantity; no self-edge; unique parent/child. These support histories are not returned by a lot list; `/lots/{lot}/events` returns a selected event projection. Source: [lot migration](../../database/migrations/2026_10_01_000900_create_waste_lot_tables.php), [AppendOnly](../../app/Modules/Waste/Models/Concerns/AppendOnly.php).

## Relationship Summary

- Company → hasMany memberships, sites, waste types, lots, pickups (owner), documents, subscriptions/invoices/payments, reports, and other tenant records.
- User ↔ Company is many-to-many through CompanyUser; UserRoleAssignment associates one user/company/role with an optional single site scope; `NULL` site means company-wide assignment.
- Site → hasMany zones, lots, stock thresholds, pickups, production volumes, and annual declarations.
- Zone → belongsTo Site; Site → hasMany Zones. WasteType → hasMany lots/threshold scopes. Lot → belongsTo Site/Zone/WasteType; Lot → hasMany composition rows/tags/events; split/group operations create lineage edges.
- Pickup → hasMany PickupLot; Pickup → belongs to owner Company, Site, Provider Company and optional Transporter Company. WasteLot ↔ Pickup is many-to-many over pickup lines over time; an active-lot uniqueness constraint prevents concurrent active pickups.
- Document ↔ WasteLot is many-to-many via DocumentWasteLot; Document → hasMany signatures and has optional stored file/site/pickup. Manifest belongs to pickup/site/document; annual declaration belongs to site and may link document.
- Company → hasOne ProviderProfile; provider has many accepted-waste and accreditation records; industrial company/provider pair has one partnership.
- CompanySubscription → belongs to company and plan, may reference a replacement subscription, and has many invoices. Invoice → belongs to company and optional subscription/credited invoice; has many invoice items and payments. InvoiceItem → belongs to invoice and may reference a tax rate/plan price. Payment → belongs to invoice and may reference proof StoredFile.
- WasteType → belongs to a global catalog item/family, regulatory code, unit, and optional packaging/color/treatment references. StockThreshold → belongs to site and optionally zone/waste type. Site → belongs to country; Zone → belongs to zone type.
- ProviderAccreditation → belongs to provider company/accreditation type/stored file and may self-reference a superseding accreditation. ProviderAcceptedWaste → belongs to company and treatment channel plus optional waste references. ProviderPartnership → belongs to owner company and provider company.
- StoredFile → optionally belongs to tenant company and uploader/deleter user/company. GeneratedReport → belongs to requester and may reference a stored file. ProductionVolume → belongs to site and optional entering user. WasteDailyStat → belongs to site and waste type and optionally treatment channel.
- Device → belongs to company and registering user; may reference revoking user and has many sync operations/tokens. SyncOperation → belongs to device and user and optionally resolver. NotificationPreference → belongs to the company/user membership. NotificationLog → optionally identifies a user and a polymorphic related record. Notification → polymorphic notifiable subject.
- Role → optionally belongs to company, may self-reference a cloned role, and has many permissions; Permission ↔ Role is many-to-many. UserRoleAssignment → belongs to company membership, role, optional site, and grantor. UserInvitation → belongs to company, role, inviter, and optional accepted user. AuditLog has polymorphic auditable/parent type+ID fields; those logical references do not have declared foreign keys.

## Unique And Check Constraints

- Identity: globally unique user email; unique company/user membership; role unique by generated company scope+name+guard; permission unique name+guard; user role assignment unique company+user+role+site scope; invitation token hash unique and one pending invitation per company/email.
- Sites/catalog: site unique company+code; zone unique company+site+code; waste type unique company+code; stock threshold unique company+site+zone-scope+waste-type-scope.
- Lots: unique public ULIDs and company+lot number; composition unique lot+material with percentage >0 and <=100; tag value globally unique by tag type and at most one active tag per lot/type; lineage unique parent+child and parent != child. Lot net weight >=0; closed status iff closed_reason is non-null.
- Provider/pickup: provider profile unique per company; accreditation unique company+type+reference+valid_from and expiry >= valid_from; partnership unique owner+provider and cannot be self; pickup unique company+pickup_number and provider != owner; pickup lot unique company+pickup+lot and lot active association constrained unique.
- Compliance: document/other tenant rows expose unique company+id targets; document-lot unique company+document+lot; signature unique document sequence; manifest unique pickup+regulatory code; annual declaration unique company+site+format+year.
- Billing/reporting/files: one subscription current flag per company; invoice number globally unique when present and credit notes require credited invoice; payment provider+provider_payment_id unique; stored file disk+path unique; production volume unique company+site+month; daily stat unique company/site/date/type/treatment-channel scope; generated report unique public ULID and company+id.
- Notifications/audit/devices: notification UUID primary key; preference unique company+user+type+channel; audit composite primary key `(id,created_at)`; device public ULID globally unique; sync client_operation_id globally unique.

## Computed And Derived Values

- Lot number and pickup/manifest references use tenant number sequences. Lot composition label derives from composition percentages. Lot version increments on update. QR value is resolved from the active QR tag.
- Pickup resource `lots` are current pickup-line snapshots; departure total is sum of loaded lot weights (defaulting to lot net weight when omitted); receipt variance is derived from departure/received mass and threshold.
- Annual declaration `submission_reference` is formatted from uppercased format code, site code, and reporting year at creation.
- Document certificate snapshot copies pickup and lot line data at upload; certificate upload creates and immediately issues the document.
- Role effective access is computed from role assignment and permissions; it is not a persisted field on User or included as tenant grants in `GET /me`.

Computed behavior sources: [CreateWasteLot](../../app/Modules/Waste/Actions/CreateWasteLot.php), [TransformLots](../../app/Modules/Waste/Actions/TransformLots.php), [PickupWorkflow](../../app/Modules/Pickups/Actions/PickupWorkflow.php), [CreateAnnualDeclaration](../../app/Modules/Documents/Actions/CreateAnnualDeclaration.php), [UploadCertificate](../../app/Modules/Documents/Actions/UploadCertificate.php), [AccessResolver](../../app/Modules/Identity/Authorization/AccessResolver.php).

`UNKNOWN — NOT FOUND IN BACKEND`: conceptual entity ownership for every global reference table beyond migration FKs; API field contracts for model classes that have no route/resource; a formal current entity count independent of the Eloquent model-file count.
